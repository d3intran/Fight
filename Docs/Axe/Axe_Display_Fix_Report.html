2. 真因

2.1 pivot 根本不在握持点上（blender_split_weapon.py 用错轴）

grip_z = min_v.z + size_v.z * 0.35     # ← 用了 Z 轴

这把斧头的长轴是 Y（172 cm），Z 方向只有 77 cm（刃高）。所谓「全长 35% 处」算出来的是一个毫无几何意义的包围盒中部点。实际后果：

  • pivot 落在了刃根上（UE 局部 Y = 0）。
  • 握柄（细段）在 UE 局部 Y ∈ [−43, 0]，尾钩在 Y ∈ [−86, −43]，大刃在 Y ∈ [0, +86]。
  • 手正握在 刃根上 ⇒ 86 cm 长的大刃整根向外伸出。

2.2 挂载朝向是试出来的

hand_rSocket.relative_rotation 被设为 (pitch 90, yaw 0, roll 0)，实测世界旋转为 (6.67, 165.06, −137.52)——完全由手骨自身朝向决定，从未按「刃朝上、刃面朝侧」设计。这个方向刚好把大刃送进躯干。

两个缺陷叠加的净效果：一根 86 cm 的刃 100% 埋在胸腔里，外部只剩 86 cm 的握柄 + 尾钩。视觉上与「斧刃被删掉」完全等价——所以第一眼判断会跑偏。

3.2 求解方法（可复现，不靠手感）

  1. 定目标姿态：斧头局部 X 轴 → 世界 +X（刃面法线朝侧向）；局部 Y 轴 → (0, −0.259, 0.966)（刃朝上、前倾 15°）。用 MathLibrary.make_rot_from_xy 构造成目标世界朝向 Wt。
  2. 标定旋转组合顺序（实测、非推断）： 
    relRot = (0,0,0)  → W = (47.0954, -97.7151, -80.1788)
relRot = (0,90,0) → W = (42.1291,  68.9880,  80.9917)

假设 World = Compose(Rel, Parent) : 残差 0.000000   ← 成立
    结论：socket 的相对旋转按 World = Compose(Rel, Parent) 组合，与直觉相反。

6. UE5 中角色与武器资产的标准处理方式

6.1 组件分离（Component Separation）

武器不做成角色骨骼网格的一部分，而是独立的 StaticMesh / SkeletalMesh，由角色蓝图里一个单独组件承载。

角色骨架里放武器（不推荐）独立组件 + socket（标准做法）
换武器要重导整个角色网格换武器只需换组件上的 Mesh 引用
武器材质/碰撞/投影和身体绑死武器可单独设材质、碰撞、阴影
无法做掉落 / 拾取 / 换装可 detach、丢到地上、被其他角色拾取
描边/外发光等后处理壳会连带复制武器不存在连带复制问题

Darius 的武器天然满足这条（SM_Darius_GodKing_Axe 是独立 StaticMesh，挂在 WeaponAxe 组件上）。

6.2 骨骼插槽挂载（Socket Attachment）

  1. 在 骨架（Skeleton） 资产上定义 socket，而不是在骨骼网格体上临时加——socket 存在骨架里才能被所有共用该骨架的网格/动画共享。
  2. socket 的父骨骼选武器专用骨（本模型已有 weapon_jnt_r，且它正好落在手心：世界 (7.590, −70.610, 117.964) vs hand_r (7.549, −70.906, 118.293)）。用 hand_r 也可以，但武器骨通常带有动画师预设的持握偏移。
  3. Pivot 契约：武器网格的原点必须落在握持点，且长轴对齐 +X（forward）； 这样 socket 的 relative_rotation 就是一个简单、可读的常量（例如 (0, 90, 0)），而不是一串试出来的魔数。
  4. 组件 relative_transform 保持单位值，把「怎么握」全部收敛在 socket 里——一个地方管一件事。
  5. 需要骨骼缩放补偿时（本模型根骨骼 100× 米→厘米），put 在 socket 的 relative_scale 上（0.01），保持与其他 socket 一致。

6.3 碰撞（Collision）

  • 武器 StaticMesh 的碰撞不要用复杂碰撞（per-poly）：代价高、形状不可控。标准做法是给武器单独建一个 Simplicity Box/Capsule，或者干脆让武器 Collision Enabled = No Collision。
  • 攻击判定不要依赖武器网格的物理碰撞，而是：
    (a) 在武器上埋 Socket（本资产已有 Socket_Blade_Tip / Socket_Blade_Edge / Socket_Pommel），运行时在这些 socket 之间做 Sweep/Box Trace；
    (b) 或用 Animation Notify + Capsule Overlap 近似。
  • 角色胶囊体只负责移动碰撞；武器碰撞通道建议单独定义（如 Weapon trace channel），避免和移动碰撞互扰。
  • 「武器不要挡路」——Collision Enabled 用 No Collision 或 Query Only，别用 Physics Body（除非要做物理武器）。

6.4 投影（Shadow）

  • Cast Shadow 保持 True（武器需要投影，否则失去立体感）。
  • 要「实体存在但不投影」时，不要靠透明材质糊弄——用组件级开关：Cast Shadow = False、Cast Dynamic Shadow as Masked、或 Hidden in Game + Visible in Scene Capture。
  • 本项目的坑：BLEND_MASKED 材质 OpacityMask=0 时自身不可见，却仍按实体投出完整阴影；必须显式开 cast_dynamic_shadow_as_masked（Python 属性名没有 b_ 前缀）。
  • 远距离/性能敏感场景用 Set Cull Distance 或 LOD 的 shadow flag，而不是整体关投影。

6.5 几何必须在 DCC 阶段处理

凡是要「永久消失」的几何，必须在 Blender/Maya 里删面，不能只靠材质隐藏——尤其是带描边/外发光壳（inverted hull）的模型，外壳是整体复制品，材质隐藏挡不住它。本项目 blender_22_strip_all.py 的做法（KDTree 找斧头顶点 → 删面 → 再删本体对象）是正确的，验收指标（全部网格 z < −0.02 的顶点数为 0）也是正确的。
