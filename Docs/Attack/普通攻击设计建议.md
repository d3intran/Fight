## 0. 结论速览

| 问题 | 结论 |
| :--- | :--- |
| **能借用神王上半身吗？** | **能，而且应该借。** 但必须**成套借**（`attack1` + `attack2` + 对应的 `*_toidle`），不能只拿 `attack1`。 |
| **下半身能一起借吗？** | **不能直接重定向。** 会重演交叉腿 / 浮空那套老问题。沿用已跑通的「上半身取源、下半身另做」分层方案。 |

## 2. 五个必须先解决的坑（每条都有数字）

### 🔴 坑 1：LoL 的攻击带 ~80° 身体旋转，而且是「左右交替 + 回正」的闭环

髋轴 yaw（用 `R_Hip − L_Hip` 的水平分量定义，骨架保证左右，不依赖任何朝向约定）：

| clip | 帧数 | 髋 yaw 相对首帧（峰值 / 末值） |
| :--- | ---: | :--- |
| `idle1` | 66 | **0.0° / 0.0°**（纹丝不动） |
| `attack1` | 74 | **−81.5° / −65.9°** |
| `attack2` | 70 | **+78.0° / +76.5°** |
| `crit` | 66 | −59.0° / −7.0° |
| `attack1_toidle` | 59 | +53.3° / **+54.7°** |
| `attack2_toidle` | 37 | +6.1° / −10.9° |
| `crit_toidle` | 37 | +6.1° / −17.5° |

**再看绝对朝向，一切就串起来了**（`idle1` 的髋朝向 = 基准 **122.5°**）：

```
idle 122.5° ──► attack1 133.3°→67.4° ──► attack2 57.1°→133.6° ──► attack1 133.3°→67.4° ──► …
                     │                                                    │
                     └──► attack1_toidle 67.8°→122.5° ──► idle             └──► attack2_toidle 133.3°→122.4° ──► idle
```

**这套 clip 是一个闭环**：attack1 向左扫、attack2 向右扫，两者**互相抵消**，最后一击接对应 `_toidle` 把身体转回基准。

**推论（违反必炸）**：
1. 只拿 `attack1` 然后 blend 回 idle ⇒ 角色**瞬间歪 55°**（attack1 末 67.4° vs idle 122.5°）。
2. 连招必须**从 attack1 起手**（attack1 首帧 133.3° 距 idle 只有 10.8°；attack2 首帧 57.1° 距 idle **65.4°**，从 idle 直接接 attack2 会弹）。
3. 连招必须**交替**：attack1 末 67.4° → attack2 首 57.1°（差 10.3°）；attack2 末 133.6° → attack1 首 133.3°（差 **0.3°**，几乎无缝）。
4. 收招必须接**对应那一击**的 `_toidle`（attack1 末 67.4° → attack1_toidle 首 67.8°，差 0.4°）。

### 🔴 坑 2：攻击不是 in-place，而且**不能照搬现有重定向的「pelvis 写回 rest」**

| clip | 根骨垂直位移 | 根骨水平位移 | 根骨水平轨迹 |
| :--- | ---: | ---: | ---: |
| `attack1` | 29.3 cm | 45.0 cm | **199.1 cm** |
| `attack2` | 31.2 cm | 28.5 cm | 176.9 cm |
| `crit` | **78.9 cm** | **145.0 cm** | 385.6 cm |
| `idle1`（对照） | 1.9 cm | 0.5 cm | 1.1 cm |

`FOUNDATIONS.md` §5 的「选项 A：把 `pelvis` 平移逐帧写回 rest」——对走路无损（源本来就 in-place），
**对攻击是致命伤：会把蹲身、起伏、前冲一起抹掉**，动作立刻变「原地比划」。

建议拆分：**垂直（蹲身/起伏）保留在动画里；水平（前冲）拆出来交给代码**（Motion Warping / `LaunchCharacter` / Root Motion 提取三选一）。
`crit` 的 78.9 cm 垂直位移是一次跳劈，那是另一套 Root Motion 设计，本次不做。

### 🔴 坑 3：下半身不能沿用「冻一帧」的做法

现有 `idle_20_build2.py` 用 `LB_FRAME = 2` 把下半身冻成走路某一帧的常量。
待机可以（人本来就不动），**攻击不行**：

| clip | 右脚轨迹 | 左脚轨迹 |
| :--- | ---: | ---: |
| `attack1` | 121.6 cm | 139.9 cm |
| `attack2` | 91.8 cm | 149.5 cm |
| `crit` | 293.4 cm | 366.2 cm |

髋部转 80° 而脚不动 ⇒ 腿会拧麻花。三条路（推荐顺序）：

| 选项 | 做法 | 代价 | 评价 |
| :--- | :--- | :--- | :--- |
| **①（推荐先试）** | 只重定向 LoL 下半身的**旋转**；`pelvis` 平移用**手调曲线**（重心左右移 + 小步前冲）；用 Foot IK / Control Rig 把支撑脚钉在地上 | 中 | 唯一能同时拿到「真实重心」和「脚不打滑」的路 |
| ② | 手摆 3~5 个关键下半身姿势（起手 / 命中 / 收招），在姿势间插值 | 中 | 可控，但不如 ① 自然 |
| ③ | 冻帧 + 整个 actor 按挥击方向转 yaw | 低 | 最省，但「站着挥斧」很僵，且和坑 1 的闭环冲突 |

### 🔴 坑 4：LoL 源骨架里的武器骨**已经被清洗掉了**

`Scripts/retarget/plan_10_src_clean.py` 明确把 `Weapon` / `Axe_Head` / `SnapWeapon` 剔了（净化后 60 骨），
理由写的是「本管线用独立 SM 战斧，应删」。

但 GLB 里的真实层级是：

```
Axe_Head ← Weapon ← R_Hand ← R_Elbow ← … ← Root ← skinned_mesh
```

**斧头是右手的子骨**，而且 `Weapon` 在动画里**被逐帧 K 帧**（见 §3.1）。
`SnapWeapon` / `SnapWeapon2Hand` 挂在 `skinned_mesh` 下，是 LoL 的「换握法目标位」标记骨。

⇒ 现在的重定向产物里**没有任何武器信息**，只能靠 `weapon_jnt` FK 反解「跟手」。
⇒ 想复现 LoL 的真实握法，需要**重导一份保留武器骨的源骨架**（或单独一份变体），让重定向把 `Weapon` 的世界变换带过来。
（替代方案见 §3.2 路线 B：离线把 GLB 量到的握法曲线烘成 `weapon_jnt` 的键，不必重导。）

### 🟡 坑 5：手指与扭转骨缺口（攻击比走路更显眼）

| 项 | LoL 源 | 我们的目标 | 后果 |
| :--- | :--- | :--- | :--- |
| 手指 | **2 节**（`L_Index1/2`） | **3 节** | 第 3 节永远不被驱动；攻击时手是视觉焦点，会看出「手指不会握」 |
| twist 骨 | **无** | **24 根**（`thigh_twist_*` / `upperarm_twist_*` …） | 保持 rest，手臂/大腿的扭转「不跟手」，像棍子 |

建议：攻击期间用 Control Rig 或一条常量曲线，给手指一个「握拳」姿势；twist 骨本次不处理（走路已经接受了这个代价）。

## 3. 武器：三件事，分开做

### 3.1 事实：LoL 的斧头相对右手**逐帧在动**

量「`Axe_Head` 在 `R_Hand` 局部坐标系里的偏移」：

| clip | 手→刃 局部偏移 | 模长 |
| :--- | :--- | ---: |
| `idle1` | 全程恒定 `(22.2, −2.2, −70.2)` | **73.7 cm** |
| `attack1` | f0 `(67.0,−46.9,−15.3)` → 挥击中 `(109.2,−28.9,−65.1)` → 收招 `(84.1,−26.5,−93.1)` | **83 → 128 → 84 cm** |
| `attack2` | f0 `(90.8,−34.9,−88.7)` → `(64.7,−14.7,−71.4)` → 末 `(67.0,−46.9,−15.3)` | **131 → 71 → 83 cm** |
| `crit` | `(67.0,−46.9,−15.3)` ↔ `(95.2,−61.8,−15.1)` ↔ `(36.4,−10.4,−75.6)` | **83 → 113 → 78 cm** |

**斧头在手里的位置会滑动 40~60 cm**，在几个「握法预设」之间跳变再插值 —— 这就是 LoL 的
`SnapWeapon` / `SnapWeapon2Hand` 机制（`anim_events.csv` 里能查到 `weapon->SnapWeapon2Hand` 事件）。

⇒ 你现在的 `hand_rSocket` 是按**「垂立单手」**调出来的（刃朝下、握在离刃 76 cm 处），
对应上表的 **idle 那一档**。直接套到攻击上，斧头会在挥击中明显脱手。

### 3.2 三条可选路线

| 路线 | 做法 | 代价 | 适用 |
| :--- | :--- | :--- | :--- |
| **A（推荐）** | 斧头几何从 `hand_rSocket` 改挂到骨架自带的 **`weapon_jnt`**；`weapon_jnt` 由 LoL 的 `Weapon` 骨重定向而来（坑 4 的重导方案）。`weapon_jnt` 就是为此准备的，现有产线已在用它做 FK 反解 | 中（一次 BP 改动 + 一次源骨架重导） | 长期正确解，之后所有攻击/技能共用 |
| **B** | 保留 `hand_rSocket`，用**动画曲线**驱动 `WeaponAxe` 的 relative transform，在 3 个握法预设之间插值 | 低 | 不想重导源骨架时的折中；预设要手调 |
| **C** | 只调一个折中 socket（取攻击段的中间值） | 极低 | 只适合「先看效果」。起手/收招会明显穿手或脱手 |

> 无论哪条，`relative_scale` 必须保持 **0.01**（抵消骨架最外层 100× 缩放），这条红线不变。

### 3.3 左手：必须真的握到斧柄

- 数据：攻击中左手到斧柄轴线最小 **1.6 / 4.7 / 4.0 cm**（attack2 / attack1 / crit）—— LoL 是真双手握。
- 现在斧头只挂在右手上，左手自由 ⇒ 会浮在斧柄旁边，或者穿过去。
- 建议：`SM_Darius_GodKing_Axe` 上加 2 个 socket（`Grip_Upper` / `Grip_Lower`），
  Control Rig 里用 Two-Bone IK 把 `hand_l` 拉到 `Grip_Upper`，用一条 float 曲线 `GripWeight` 控制权重。
- ⚠️ **`GripWeight` 不能全程 = 1**。LoL 的左手是「挥击时才握上」的：
  `attack1` 左手到轴线 f0 = 26.7 cm → 挥击瞬间 150 cm（脱开）→ 收招回到 4.7 cm。
  曲线要按这个形状做，否则左手会在起手时被 IK 突然吸到斧柄上。

## 7.5 重定向侧要做什么（据 2026-09-20 实际管线修正）

⚠️ 本节是对 §2「坑 4」和 §5 步骤 1 的补充。**之前那份 `Docs/Retarget/HANDOFF.md` 已过时** ——
它停在「下一步待确认」，而实际路线是 **手动 Retarget Pose 标定 + 分层合并**。
完整复盘见 `Docs/Retarget/复用LoL上半身_复盘与做法.md`。

**关键认知**：当初重定向「失败」不是 IK Rig / Retargeter 配不出来，而是漏了
**Retarget Pose 标定**（`hand` / `foot` 是链尾骨，`Direction` 方法定不出方向 ⇒ 偏移留 0），
而这一步**不报错**。**但只要上半身，当初最难的几块（腿/脚/脚趾链尾、髋宽 −22%、骨盆朝向）全都不在范围内**：

| 维度 | 当初（全身） | 现在（只上半身） |
| :--- | :--- | :--- |
| 链数 | 源 9 / 目标 29 | **约 13 条** |
| 链尾骨（最难） | `hand_l/r` + **`foot_l/r`** + 脚趾 | **只剩 `hand_l/r`** |
| 比例问题（髋宽/腿长/浮空） | 全部 | **完全不涉及** |
| 骨盆/根骨朝向 | 交叉腿 65/65 帧 | **分层合并直接丢掉源的 `pelvis`** |

⇒ 所以 §5 的步骤 1 要改成：**重导一份保留 `Weapon` 骨的源骨架变体 → 手工建一个「只含上半身链」的
IK Rig + Retargeter → 标定 `hand_l/r` → 批量重定向 → 再分层合并**。别去复活归档的 `RTG_LOL_to_Darius`。
