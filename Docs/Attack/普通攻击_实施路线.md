## 0. 一句话判断

**不要再走 UE IK Retargeter 手工标定那条路。**
先把「LoL 上半身 → Darius 骨架」做成一个**离线、纯脚本、能出数字**的实验；
它成不成用数字说话，再决定后面怎么铺。

理由：上次翻车的那根骨（`hand_l` / `hand_r` 是**链尾骨**）恰恰是 UE IK Retargeter 的
`Direction` / `CHAIN_TO_CHAIN` **从原理上处理不了**的 —— 它靠「子骨方向」定义本骨朝向，
链尾没子骨 ⇒ 偏移留 0 ⇒ 必须人眼手工补，而手工结果**不可回归**。
世界空间传递不走这条路。

## 1. 两条路对比

| 维度 | UE IK Retargeter（手工标定） | **离线世界空间传递（推荐）** |
| :--- | :--- | :--- |
| **链尾骨 `hand_l`/`hand_r`** | ❌ 靠子骨定方向，链尾必须手工补 ← **上次翻车的正是这里** | ✅ 直接用世界旋转差反解，**不依赖子骨** |
| 人工介入 | 必须人眼标定 Retarget Pose | **0**，全脚本 |
| 可回归 / 幂等 | 差（标定结果是资产里的状态） | 好（参数是脚本常量） |
| 需要 UE 源骨架带 `Weapon` 骨 | 需要（得先重导一份源骨架变体） | **不需要**（Blender 直接读 GLB / FBX） |
| 迭代速度 | 开编辑器 | 命令行 |
| 已有轮子 | `Content/.../IK/RTG_Darius`（Mixamo 专用） | `Scripts/anim/anim_80_axe_retarget.py` |

### 为什么 `anim_80` 能直接复用

它已经是**世界空间纯旋转增量传递**（`Scripts/anim/anim_80_axe_retarget.py`，原本用于 Mixamo → Darius）：

```python
R_world      = M_src_cur @ M_src_rest.inverted()   # 源骨在世界的纯旋转增量
M_tgt_desired = R_world @ M_tgt_rest               # 套到目标骨的 rest 上
# 再用父级 rest 世界矩阵反解成目标局部旋转
```

两个直接好处：
1. **不需要子骨方向** ⇒ `hand_l` / `hand_r` 与其它骨一视同仁，链尾问题从根上消失。
2. **与单位 / 缩放无关** ⇒ GLB 里那点 ×1.33 的尺度差**完全不影响旋转部分**。

它的映射表已经覆盖了上半身全部骨（`Spine`/`Spine1`/`Spine2` → `spine_01/02/03`、
`Neck`/`Head`、`Shoulder` → `clavicle_*`、`Arm` → `upperarm_*`、`ForeArm` → `lowerarm_*`、`Hand` → `hand_*`）。
换源只需改映射表 + 加白名单。

**目标**：产出 `attack1` 的上半身在 Darius 骨架上，并**用数字判断够不够好**。
⚠️ 这一步**不动任何现有资产**（产物落 `Saved/`，验证通过再进第二步）。

| 1.1 | 复用 `anim_80` 改一个 `atk_10_lol_upper_retarget.py`：源换成 `darius_skin15_all_anims.glb` 的 `attack1`；**白名单**只传 `spine_01` 子树 + `Weapon → weapon_jnt`；**显式写死** `Spine1 → spine_01 + spine_02`、`Spine2 → spine_03` |

**1.2 的门禁指标**

| 指标 | 门槛 |

| 逐骨世界方向夹角 vs 源（上半身） | **均值 < 8° / P90 < 20° / max < 35°**（沿用 `FINAL_Retarget_Plan` 的 G1） |

**分支**：全过 → 进第二步；**只有 `hand` 不达标** → 才回头用 UE 手工标定补这一根骨（有针对性，不是重来）。

## 4. 需要你定的一件事：idle 的上半身换不换？

**我的建议：先只换攻击，idle 不动。**

- 实测 LoL 源 `idle1` 的脊柱是**后仰**的（`Spine1` 9.4° 向后 / `Spine2` 10.6° 向后 / `Neck` 24.9° 向后），
  是给**俯视角**读轮廓的剪影，搬到过肩机位**不一定比现在的 Mixamo 待机好看**。
- 而**攻击必须用 LoL**（没有别的资产有「德莱厄斯挥巨斧」）。
- 两者风格不一致的地方（idle 单手垂持 84.7 cm → 攻击双手握上 1.6~4.7 cm）**LoL 自己也是这样**，
  过渡时手会移动，是**真实且正确的**。
- 等第一步的管线跑通，顺手产出 LoL idle 的上半身几乎零成本，那时做 A/B 再定。

## 5. 已知风险（诚实清单）

| # | 风险 | 应对 |
| :--- | :--- | :--- |
| 1 | LoL 源与 Darius 目标的**全局朝向基准**可能不同（`anim_80` 里那个 `R_yaw_fix`） | 它是一个**可测量的单一参数**（用 `idle1` 的髋轴 yaw 差定），第一步 1.2 的门禁会暴露它 |
| 2 | `Spine1/Spine2 → spine_01/02/03` 的 2→3 分配规则可能选错 | 写死成脚本常量，试 2~3 组，用 1.2 的逐骨夹角选最优 |
| 3 | LoL 上半身在**大幅扭身**时（髋转 80°）可能超出目标的肩关节可达范围 | 1.3 的渲染图 + 第二步的下半身方案① 一起看；必要时按比例压缩躯干 yaw |
| 4 | GLB 源与 `.anm` 源的**数值一致性**已验证（`Root` \|T\| = 95.71 对齐），但只验了 `Root` 一根 | 1.1 里对 `Pelvis`/`Spine1`/`Head` 再各验一根 |
| 5 | 手指 3 节 / twist 骨 12 根（上半身）仍不被驱动 | 攻击里用 Control Rig 补「握拳」常量姿势；twist 骨本次不处理 |
