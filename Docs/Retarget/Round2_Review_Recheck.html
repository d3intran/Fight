第二轮评审复核 · 对「精简实战版」方案的逐条校准

复核方式：本地磁盘实测 + 官方发布状态核实 + 前一轮已建立的资产实测数据｜2026-09-18
总评：这一轮的价值在于「真的去查了本地磁盘」——这是三份方案里第一个做实地核实的，值得肯定。它值得采纳的实质意见有三条（Stride Warping 优先、先做垂直切片、暂不引入 Cascadeur）。但它有三个继承性错误、一个方向性错误、一个退化（把我上一轮明确否掉的 |Pitch| ≤ 5° 又搬了回来），以及一个结构性问题：把一个"无量化门禁 + 3 天交付"的计划当成了精简的优点，而这恰恰是上次 26.8° 翻车的模式。

1. 它做对的事（实测复核后确认成立）

1.1 本地确无 2XKO 资源 —— 它查对了

我独立复核了全盘：

全盘搜索 2XKO 目录       → 无
全盘搜索 nav_std 文件     → 无（只命中 LOL 的 darius_base 音频/特效，不是 2XKO）
E:\UE\Assets 下 2XKO 动画 → 无，只有 God King Darius 2XKO.fbx（单个网格体）

它是对的本地确实没有 2XKO 客户端或解包动画库，我上一版把方案 C 列为"第一个半天去验证"，它提前把这一步做掉了，这是净收益。

1.2 但它的结论下得过重 —— 因为前提过时了

它写「2XKO 目前处于有限 Playtest 封测阶段，若无客户端资产，把方案 C 当作第一前提是空中楼阁」。
实测（官方渠道，2026-09-18）：
  • 2XKO 已于 2025-10-07 PC 抢先体验，2026-01-20 正式发售（PC / PS5 / Xbox Series X|S），免费游戏；
  • 2026-08-20 Riot 公告：2026 年 12 月结束积极开发，转入维护模式；最终内容更新在 10 月（Lux 已在 9/9 上线，Samira 10 月）；
  • 服务器继续在线，PC 仍可免费下载；且为回馈玩家，全部格斗家免费解锁；
  • 国服另有「先锋测试服」（限号不删档，需到官网申请资格）。
所以准确定性是：不是「封测不可得」，而是「需要一次几十 GB 的下载 + 一次解包」。 对照一个要投入 12+ 天的重定向工程，几小时的下载成本换「locomotion 零重定向误差」，性价比判断完全不同。

1.3 另外两条实质意见，我认同并采纳

它的意见我上一版的处理修正
步幅用 Stride Warping，不要「改引擎速度迁就动画」 我建议「设 MaxWalkSpeed = V_anim」，把 Stride Warping 只放在风险 R4 的缓解措施里 接受重手感优先是对的。修正为：以目标移速（500~600）为锚 → 用 Stride Warping 自适应展开步幅；仅当 Stride Warping 仍压不住（超出手感可接受范围）才回头调速度。
但它把「改速度」等同于「硬降到 350」是稻草人——V_anim 从未被测过，降不降、降多少本来就该先测再定，而"测隐含速度"正是我计划里的阶段 0。
先做垂直切片（走跑+普攻+技能姿态）再铺开 我给了 8 阶段 12.5 天的完整路线 部分接受拆分里程碑是对的：M1 垂直切片（源净化 + IK Rig + 比例补偿 + 去倾斜 + 步幅闭环 + ABP，约 3.5 天）→ M2 风格改造/次级运动/twist 驱动/全量动作/回归。
但「2~3 天完成」不可信：它砍掉的正是验证环节。参照本项目的实际历史——今天修一个"应该 5 分钟"的斧头显示问题，从定位到落盘花了近 3 小时；上次重定向因为跳过验证直接翻车成 26.8°。**3 天垂直切片可以接受，3 天交付整套行走跑跳打不行。**
暂不引入 Cascadeur我列为"阶段 4/5 手工超 2 天再考虑"接受结论
但理由错了：它说「309 骨远超免费额度」——Cascadeur 本来就只用于白名单裁剪后的源骨架（~45 骨），远在 120 骨上限内。真正的拒绝理由应是"多一个跨软件环节的往返风险与时间成本不划算"。

2. 它继承 / 引入的错误

2.1 仍然沿用「2.47 m」——而且这次用在了解算里

它写「2XKO 是 2.47m 写实巨人」，并在阶段 3 写「以 2.47m 腿长自适应展开步幅」。
实测：目标网格 z 上限 = 2.06 m（UE SK bounds z = 3.8 ~ 206.2 cm；源 FBX 网格 z 0.04 ~ 2.06）。 2.47 这个数字源自 AGENTS.md 里一句未核实的旧注，我上一轮已经把它连同 A3 的机理一起修正了。
影响：步幅/Stride Warping 的量级推算会偏 20%，去倾斜的肩高/腿长比例也会跟着错。

2.2 髋宽偏差的物理解释反了（结论碰巧对，机理错）

它说：「LOL 德莱厄斯是 MOBA 倒三角身材、髋极窄；2XKO 是写实巨人、骨盆宽大」。

度量LOL 源2XKO 目标谁更宽
左右髋间距 / 身高26.55 / 187.21 = 0.14180.2048 / 1.8502 = 0.1107LOL 相对宽 28%

方向是反的。后果：旋转复制后，目标膝盖间距会比源窄约 5.7 cm（髋间距差 × 缩放），出现"夹腿"。要恢复源的站姿，正确操作是把目标双腿外展——它给的处方（外展偏移）方向对，但因为它相信"目标是宽骨盆"，幅度会算反（会往"收"的方向越调越糟）。这类"结论对、机理反"的错误最危险，因为它会在调参阶段把人带偏。

2.3 把我上一轮明确否掉的 |Pitch| ≤ 5° 又搬了回来

它阶段 3 写：「将待机/跑动视线强制拉回地平线水平面（|Pitch| ≤ 5°）」——这与我在上一轮批评 Gemini 的 G2 是同一条：
逐帧强制头部绝对水平会剥夺自然点头（跑步时头本来就该随躯干有 3°~8° 周期性起伏），在 attack/spell 的发力帧（实测颈段最大 +69°）会产生明显"头部卡住"感。
正确做法（我上一轮已给出）：① 低通滤波估出"俯视补偿基线"，只减去基线；② 关键帧约束（站立帧 |pitch| ≤ 6°，发力帧放宽 ≤ 25°）；③ 指标改为「头部相对躯干的偏置标准差 < 4°」。

2.4 仍然没有校验去倾斜的数据前提，而且作用对象搞错了

它说「躯干彻底抹除 56° 俯视造成的'仰面望天'」。但实测（相对 bind pose）：

动作躯干轴颈段头骨轴
idle1+0.4°（不动）−32.1°−12.1°
run+34.3°+52.3°+10.8°
run_fast+61.9°+63.8°+22.4°
  • 「仰面望天」不在躯干，在 Neck(−32°) + Head(−12°)。对躯干做「去倾斜 100%」在 idle 上等于什么都没做，而如果按"反向补偿"施加，反而会把 idle 的躯干推成前倾。
  • 真正该被"去"的是 run 家族 34°~62° 的前倾——而它写成「待机/跑动视线」，把 idle 和 run 当成同一个问题处理，两者需要的补偿方向和工作部位都不一样。

3. 结构性缺口：它把一个"没有量化验收"的计划当成了优点

它的 4 阶段计划里，唯一的量化指标是 |Pitch| ≤ 5°（而且这条本身是错的）。
没有：关节位置误差门禁、足部漂移门禁、隐含速度 vs 速度门禁、生理限位、穿模检查、A/B 渲染对比。
而它同时把周期压到 2~3 天。

「压缩周期 + 取消量化验收」这个组合，与本项目 2026-09-18 那次 26.8° 翻车的成因完全同构——当时也是"只验了能导入就交付"。它批评我的计划过度工程化，但它砍掉的不是工具链（Control Rig 补偿、Stride Warping、Speed Planting、双手 IK 它都留着），砍掉的是验证环节。

另外几处遗漏（与我上一轮列的一致，它没补）：24 根 twist 骨的驱动策略（源侧无对应）、披风/次级运动（阶段 4 完全没提，连它自己认可的 Gemini 披风分离方案也没写进去）、attack/spell 的姿态改造（阶段 1~3 只覆盖 walk/run）、309 骨里大批无源骨的处置。

4. 合并后的决策（6 个拍板点，附实测依据）

#它的决策我的最终建议实测依据
1UE IK Retargeter + DCC 预处理为主线一致，但把 2XKO 官方动画从"第一前提"降为可选的、需先下载验证的增强项（不是"空中楼阁"，也不是"必须先做"）本地实测无 2XKO 资源；但 2XKO 已公开发售、PC 免费下载、全角色免费

3Stride Warping 适配步幅采纳。先测动画隐含速度做基线，再以目标移速为锚用 Stride Warping腿长/身高差仅 4.4%（不是它以为的"短腿对长腿"）
4先用 Run 贯通，或降速重采样出 Jog采纳。补一条：Walk 缺失必须写进计划显式项，别让 BlendSpace 假设它存在实测 46 个动作里无 walk
5髋/颈补偿写在 Control Rig 运行时层一致。但幅度必须反解而不是手调：以"两膝间距 / 身高"和"头顶高度 / 身高"与源一致为方程求解髋宽 −22%（目标更窄）、颈长 +84%（目标更长）
