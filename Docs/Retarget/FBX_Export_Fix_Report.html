结论：项目历史上四个批量重定向脚本都在「挂着 action 的状态下导出 FBX」， 导致 Blender 把导出瞬间的 pose 写成骨架的节点变换。产出的 FBX 里 bind pose 完全错误（关节间距偏差最高 15.4%）。四个脚本已全部修复， 修复后实测偏差 5.926e-07。

二、根因定位：三选一实验

纯推理无法判断 Blender 导出器的行为，所以直接做对照实验 （plan_17_export_probe.py）：同一场景内用三种方式各导一个 FBX， 再把三个文件逐个重新导入回读比对。

导出方式骨骼动画数间距偏差判定
A 挂 action + frame_set(20)（= 历史做法）
all_actions=False		 17915.843e-02BROKEN
B 先清 pose
all_actions=False		 17911.198e-07OK
C 先清 pose
all_actions=True		 179461.198e-07OK

读法：

  • A 直接复现了历史 bug（5.8% 偏差）—— 确认根因就是「挂着 action 导出」。
  • B 证明「清 pose」是修 bind pose 的必要且充分条件 —— 但它只导出 1 个动画， 且在 all_actions=False 下导出器究竟选哪个 action 是不确定的 ⇒ 不能用于批量。
  • C 是唯一可行的方案：bind pose 正确 且 46 个动画全部保真。
为什么「逐 action 导出」不可行：导出器需要 action 处于挂载状态才能烘焙它的动画， 但挂载动作就会让 pose 变成该动作在当前帧的值，从而污染骨架节点。 两者在同一时刻互斥 —— 所以只能一次性导出全部 take，让导出器自己管理 action 的挂载/卸载。

2.1 四个受影响的脚本

脚本原写法
blender_51_retarget_v4.py第 286 行 action = None，但循环内第 289 行又挂回 action，且循环里没有 frame_set ⇒ frame 停在上一个循环遗留处
blender_30_batch_retarget.py同模式（第 175 / 178 行）
blender_50_retarget_v3.py同模式（第 263 / 266 行）
blender_10_retarget.py无 action = None，直接在烘焙循环后导出 ⇒ frame 停在最后烘焙帧

三、修复

# 导出前：断开 action 并清空全部 matrix_basis
if arm.animation_data:
    arm.animation_data.action = None
for pb in arm.pose.bones:
    pb.matrix_basis = Matrix.Identity(4)      # 光设 action=None 不够稳，必须逐个清
bpy.context.view_layer.update()

# 再以「单文件多 take」导出（all_actions=False 无法保证 bind pose）
bpy.ops.export_scene.fbx(
    filepath=out, use_selection=True, bake_anim=True,
    bake_anim_use_all_bones=True, bake_anim_use_nla_strips=False,
    bake_anim_use_all_actions=True,                 # ← 关键
    bake_anim_force_startend_keying=True,
    bake_anim_simplify_factor=0.0,                  # ← 不简化曲线
    add_leaf_bones=False, primary_bone_axis='Y', secondary_bone_axis='X',
    apply_unit_scale=True, global_scale=1.0, armature_nodetype='NULL')
  • blender_51_retarget_v4.py / blender_30_batch_retarget.py / blender_50_retarget_v3.py： 导出循环改为上述写法，输出契约变为单文件多 take（A_Darius_All_TP.fbx）。
  • blender_10_retarget.py：补 rest 复位，并标注 DEPRECATED （其「单文件单动作 + all_actions=False」契约未经验证，勿用于新工作）。
  • anim_12_import_snap.py：加注释说明输出契约变更与旧产物废弃。

一条更普适的教训：「脚本没报错、文件也生成了」与「产物正确」之间没有必然联系。 本轮 17 个文件全部生成成功、大小正常、导入 Blender 与 UE 都不报错 —— 但其中 15 个是坏的。 批量导出必须配一个独立的外部审计器，且审计判据要选「缩放不变量」这类与实现无关的量。
