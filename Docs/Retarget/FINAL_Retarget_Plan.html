5. 去倾斜：本版最关键的架构修正

5.1 为什么不能逐动作给离散常量

按绝对角反解出的补偿量是方向相反的：

动作绝对角（躯干/颈段）目标绝对角补偿量（躯干/颈）
idle1−7.2° / −24.9°−2° / +5°+5.2° / +29.9°
run+26.7° / +59.5°+18° / +22°−8.7° / −37.5°
run_fast+54.3° / +71.0°+22° / +25°−32.3° / −46.0°
run_homeguard+44.8° / +72.9°+22° / +25°−22.8° / −47.9°
颈部补偿在 idle 与 run 之间相差 67.4°（+29.9° → −37.5°），idle→run_fast 相差 75.9°。
若按动作离散给常量，Idle↔Run 的 0.2s 状态淡化会让颈部在 0.2 秒内甩过 67° —— 肉眼可见的"触电式抽搐"。

5.2 正确的解法：把偏置定义成「速度」的连续函数

躯干偏置  offsetTorso(v)：  v=0 → +5.2°      v=v_run → −8.7°      v=v_fast → −32.3°
颈部偏置  offsetNeck(v) ：  v=0 → +29.9°     v=v_run → −37.5°     v=v_fast → −46.0°
（v 为 M0 实测出的各动画隐含接地速度 cm/s；用 CurveFloat + MapRange 在 ABP 里驱动）
  • 为什么这能根治：速度是连续量，玩家从站立到全速会经过 0→600 的连续区间，偏置随之连续变化，不存在状态切换瞬间的角度阶跃。玩家读到的语义是"他随着加速逐渐压低身体"，而不是"脖子突然一甩"。
  • 为什么必须在运行时层：偏置的自变量是运行时速度，离线烘焙进 FBX 就失去了这个自变量。这是"放 Control Rig 而非烘焙"的真正理由。
顺带纠正一个流传的论证："烘焙进 FBX 会在融合时抽搐、放运行时层就不会" —— 这个理由不成立。 淡化（Crossfade）插值的是两段姿态，姿态差 67° 就是 67°，无论这 67° 是烘焙来的还是运行时叠加的，淡化期内的摆动完全一样。 运行时层的价值不在于"避免抽搐"，而在于它提供了施加阻尼的钩子（Inertialization / Spring），以及让偏置能随速度连续变化。 本版两者都用：速度曲线消除阶跃（主），Inertialization 处理姿态本身的切换（辅）。

5.3 去倾斜深度：保留角色性格

idle 的抬头（颈 −24.9° + 头 −12.1°，合计 ≈37°）100% 抹除会让神王看起来"垂头丧气"。定案：只还原 ~70%，即 颈补偿从 +29.9° 降到 +21°，保留约 9° 的上扬（在第三人称里读作"睥睨"，符合角色）。

run 家族压到人体冲刺合理区间（躯干 18°~22°），不保留过量。attack/spell/dance/recall 不做去倾斜（小幅保留其设计幅度）。

6. 三处已知暗礁与对策

#暗礁机理对策
1Idle→Run 折颈暴冲（本轮新增，已量化确认） 颈部补偿方向相反、相差 67.4°；离散常量 + 0.2s 淡化 = 肉眼可见甩头 §5.2 的速度连续偏置曲线（主）+ Inertialization（辅）+ idle 只还原 70%（降幅）

3目标侧无源骨 24 根 twist + 150 面部 + 披风链 + 护具骨在源侧都没有对应 twist 程序化驱动；面部留参考姿态（后续单独做）；披风用 AnimDynamics；护具骨跟父骨插值
