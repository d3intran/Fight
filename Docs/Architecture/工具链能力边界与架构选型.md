# 工具链能力边界与架构选型

> 2026-09-21 · 回答三件事：① 8000 端口 MCP 与 UE 官方 Python 接口各能做到什么；
> ② 「复制一个网格做实验」是不是必须；③ 为什么操控的是蓝图、要不要改成 Pawn / C++。
> 全部结论来自本机实测（读引擎源码 + 本工程落盘快照），非推测。

## 一、两条通道，别混为一谈

本工程有**两条完全独立**的自动化通道：

| | **A. 内置 MCP** | **B. 官方 Python Remote Execution** |
| :--- | :--- | :--- |
| 入口 | `http://127.0.0.1:8000/mcp`（`Config/DefaultEditorPerProjectUserSettings.ini` 里 `ServerPortNumber=8000` / `ServerUrlPath=/mcp` / `bAutoStartServer=True`） | UDP 广播 **6766** 发现实例 → TCP 命令通道 |
| 客户端 | `Scripts/ue_mcp.py`（手写 MCP over HTTP 客户端） | `Scripts/ue_remote.py`（官方 `remote_execution` 模块，`MODE_EXEC_FILE`） |
| 提供者 | `ModelContextProtocol` 插件（UE 5.8 自带） | `PythonScriptPlugin`（UE 5.8 自带） |
| 暴露什么 | **Toolset** —— Epic 预写的**类型化工具**，每个工具一份 JSON Schema | **任意 Python**，跑在编辑器的 Python 环境里 ⇒ 完整 `unreal.*` API 面 |
| 安全护栏 | 有（只能调已注册的工具） | **没有**（你自己负责正确性和不崩编辑器） |
| 本工程用量 | ≈ 0 | **≈ 100%** |

**一句话**：MCP 是「**窄而安全的现成积木**」，Python 是「**宽而万能的白刃**」。

## 二、MCP 的真实上限 —— 已从 4 个 toolset 扩到 53 个

### 2.0 先搞清楚 MCP 的结构：只有 3 个「元工具」

MCP 暴露给客户端的**不是**几百个工具，而是 **3 个元工具**（2026-09-21 编辑器运行时实测）：

| 元工具 | 作用 |
| :--- | :--- |
| `list_toolsets` | 列出当前**已注册**的全部 toolset（名称 + 描述） |
| `describe_toolset` | 取某个 toolset 的完整工具清单 + 入参 schema |
| `call_tool` | 按名调用：给 `toolset_name` 调 toolset 工具，不给则调顶层工具 |

所以流程是 **两级**：`list_toolsets` → `describe_toolset` → `call_tool`。
这也意味着「MCP 能做多少事」**完全取决于当前启用了哪些插件**。

## 三、Python 通道（`ue_remote.py`）的能力边界

**能做到**：`unreal` 模块的**全部**接口 —— `EditorAssetLibrary` / `AnimationLibrary` /
`UAnimationDataController` / `SkeletalMeshEditorSubsystem` / `IKRetargeterController` /
`unreal.get_editor_subsystem(...)` / PIE 控制 / `unreal.load_object` / 关卡 actor 操作 / FBX 导入导出。

**已知的边界与坑（全是实测踩出来的）**：

| 坑 | 表现 | 防护 |
| :--- | :--- | :--- |
| 脚本里出现 `.py` 字样 | UE 嗅探机制误判为路径 ⇒ **静默不执行** | 一律落盘传路径（`ue_remote.py` 已封装） |
| 阻塞游戏线程 | 长脚本卡编辑器；Slate 模态弹窗会让它**彻底无响应** | 拆小步；`editor_dialog.py --auto` 先发 `WM_CLOSE` |
| PIE 期间 `load_asset` 被拒 | 返回 None，日志 `The Editor is currently in a play mode.` | 改用 `unreal.load_object` / `unreal.find_object` |
| PIE 期间 `save_asset` 返回 False | 只改内存；运行中的 PIE 也不重读属性 | 退出 PIE 再存，再重进 |
| 批量资产操作**不幂等**且**大多静默** | 目标包名已存在 ⇒ Interchange 静默跳过工厂；`run_batch_retarget` 崩编辑器 | 每个脚本自带**前置状态检查 + 后置数字门禁** |
| 无事务 | 崩了就崩了 | 串行、小步、备份 |

## 四、关于「复制一个 `SK_Darius_GodKing1` 做实验」

**不需要，而且不建议。** 我说的第一步是产出一个**新的 `AnimSequence`**，不是复制网格：

| | 动的东西 |
| :--- | :--- |
| 目标网格 `SK_Darius_GodKing` | **一个字节都不动** |
| 骨架 `SK_Darius_GodKing_Skeleton` | **不动** |
| 第一步的产物 | 一个**新动画**（例：`A_Darius_Attack1_Upper_LOL`），实验期落 `Saved/`，验证通过才进 `Content/` |
| 第一步在哪跑 | **连 UE 都不进** —— Blender 里读 GLB 源 + 读目标 FBX，导出 FBX |

**为什么不复制网格**：
1. 这个项目已经踩过 `Interchange 导入静默跳过工厂`（目标资产名已存在时静默跳过）和
   `资产被加载过之后再 delete_asset 会崩编辑器` —— **副本只会制造垃圾和崩溃风险**。
2. 复制网格不会让任何问题变简单：所有失败模式都在**骨架/动画**层，与网格无关。
3. 唯一需要「复制」的地方是分层合并脚本里的 `duplicate_asset(基准动画, 新路径)` ——
   那是复制**动画**（为了保住骨架 / 帧率 / 长度 / 轨道集合），与网格无关。

## 五、关于「操控的是蓝图对象不是 C++ 对象，为什么不是 Pawn」

### 5.1 它**就是** Pawn

从 `Saved/BP_DariusCharacter_Export.t3d` 里读到的真实父类：

```
ParentClass="/Script/CoreUObject.Class'/Script/Engine.Character'"
```

`ACharacter` 的继承链是 **`ACharacter` → `APawn` → `AActor`**。
所以 `BP_DariusCharacter` **是一个 Pawn**，只是名字里没有 "Pawn" 三个字。

它从 `ACharacter` 继承到 `UCapsuleComponent` + `UCharacterMovementComponent` + `USkeletalMeshComponent`，
自己又在 SCS 里加了：`SpringArmComponent`（CameraBoom）· `CameraComponent` · `CharacterMesh` · `WeaponAxe`。

### 5.2 「蓝图对象 vs C++ 对象」这个二分是假的

蓝图**编译出来就是 C++ 类**（`UBlueprintGeneratedClass`，派生自 `ACharacter`）。
运行时两者没有区别 —— `GetWorld()->SpawnActor<ACharacter>()` 一样能拿到它，
`Cast<ACharacter>()` 一样能转。**区别只在「逻辑写在哪里」**：

| | 蓝图 `BP_DariusCharacter` | C++ `AFightCharacter` |
| :--- | :--- | :--- |
| 现状 | **全部逻辑在这**（移动 / 机位 / Enhanced Input / 跳跃） | `Source/Fight/` **还是默认模板** —— 只有 `Fight.h` / `Fight.cpp` / `Fight.Build.cs`，**没有任何自定义类** |
| 强项 | 调参所见即所得（弹簧阻尼、相机偏移这种）；热改不用编译 | 复杂状态机 / 连招树 / 输入缓冲 / 结构体枚举 / 性能 / diff 友好 / 可单测 |
| 弱项 | 复杂逻辑的图会变面条；合并冲突难解；性能敏感代码不合适 | 改一次要编译（可用 Live Coding 缓解） |

### 5.3 建议：不是「改成 Pawn」，是「把战斗逻辑搬到 C++」

这正是 `AGENTS.md §0.2` 已经写好的方向（`AFightCharacter` + `AFightPlayerController`）。落地方式：

1. **先只加一个空的 `AFightCharacter : public ACharacter`**（**不带任何组件**，避免与蓝图 SCS 里的组件重名冲突）。
2. 在编辑器里把 `BP_DariusCharacter` 的 **ParentClass 改成 `AFightCharacter`**（Reparent）。
   - ⚠️ **动手前先备份 `BP_DariusCharacter.uasset`**；Reparent 后要逐项核对
     `SpringArmComponent` 的阻尼/偏移、`CharacterMovementComponent` 的 `MaxWalkSpeed`/`JumpZVelocity`、
     `WeaponAxe` 的 socket 与相对变换是否还在。
3. **门禁**：PIE 里走路 / 跳跃 / 机位手感**与 reparent 前完全一致**（关卡 7 个基线 actor、鞋底高度、弹簧拉伸量都要复测）。
4. 通过后再逐步往里搬：输入 → 战斗状态机 → 连招 → hitbox → 顿帧。
5. **手感参数继续留在蓝图里**当默认值覆盖（改 C++ 默认值要编译，改蓝图 instant）。
